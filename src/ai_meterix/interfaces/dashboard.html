    Help

    AI Meterix measures what AI work costs on this machine: the energy the chip uses, the tokens each model reads and writes, and what both cost in USD. This page explains every number on the dashboard and how to run the service.

    Getting started

    Run these in a terminal, in the project folder (with uv run in front if you use uv):

    aimeterix doctor     # once: what can this machine measure?
aimeterix profile set --rate 0.30   # once: your electricity price per kWh
aimeterix start      # start the agent, proxy and API in the background
aimeterix health     # check everything runs and measures (exit code 0 = healthy)
aimeterix stop       # stop all three; data in memory is written first

    Then open this page at 127.0.0.1:8788 in your browser. Point your AI apps at the proxy (port 8787 on this machine by default; change the port with AIMETERIX_PROXY_PORT) instead of calling the model server directly, so their calls are counted. Logs are in ~/.aimeterix/logs. The services keep running after you close the terminal, but not after a restart of the machine: run aimeterix start again.

    How it works

    agent
    Samples the chip every few seconds: power, energy, CPU, GPU and memory, and which processes use them. This is where every energy figure comes from.
    proxy
    Sits between your apps and the model server (local llama.cpp or a cloud API). It forwards each call unchanged and records the model and the token counts. It never stores prompts, answers or API keys.
    serve
    The API and this dashboard. It only reads and computes; it changes nothing unless an admin asks it to.

    aimeterix start runs all three in the background with one command, which is what you normally want. You can also run any of them on its own:

    • In the background: aimeterix start proxy (or agent, serve, or any two).
    • In the terminal, in the foreground, to watch its log: aimeterix agent, aimeterix proxy or aimeterix serve; stop it with Ctrl-C. Options given there, such as --port or --interval, apply to that run only.

    They are separate processes on purpose: if one stops, the proxy keeps forwarding, so your apps keep working. aimeterix stop --keep-proxy stops the other two and leaves the proxy running. Services started in the foreground show as stopped under Is it measuring?, because only start records them.

    Accounts and sign-in

    There are two accounts. user can see everything. admin can also change prices, the cost profile and settings through the API or the command line. On first sign-in the password is the account name and you must choose a new one. To reset a forgotten password, run aimeterix password user (or admin) on this machine.

    Signing in keeps you logged in with a secure cookie for this browser only. Use Log out on a shared computer. This dashboard is read-only: changes are made with the commands in Command reference.

    Choosing dates

    Pick Today, the last 7, 30 or 90 days, or enter your own dates and press Show (up to 366 days). Days are local days on this machine, midnight to midnight. Every panel uses the same range.

    The four numbers

    Cost
    Everything this range cost: energy, the share of fixed fees, and tokens sent to paid models. The small line splits it into energy and tokens. Local models have no token price, so their cost is their energy.
    Energy
    The energy the chip used, measured by the agent, in watt-hours (Wh). 1,000 Wh is 1 kWh, the unit on your electricity bill.
    Tokens
    All tokens read and written by every model through the proxy: input, output and cached tokens together. The small line shows input and output.
    LLM calls
    How many requests went through the proxy. Calls that skip the proxy are not counted.

    Energy per day

    Each bar is one day. Its height is the energy the chip used; the colors show who used it:

    A model name
    Energy used by the processes that run that local model.
    (other apps)
    Energy used by everything else on the machine: browser, editor, and so on.
    (idle overhead)
    Energy nobody used, such as the chip waiting at idle. Fixed fees for hours the machine was off also land here.
    other models
    When more than six models ran, the smaller ones are grouped under this name.

    Hover or tab to a bar to see each part in Wh. Show as a table gives the same numbers as text.

    Is it measuring?

    Healthy means all three processes run, the database answers, and the newest hardware sample is less than 5 minutes old. Otherwise the panel says Needs attention and lists what is wrong.

    agent, proxy, serve
    Running or stopped, with how long each has run. Processes started some other way than aimeterix start show as stopped here, even when they work.
    database
    Whether it answers, and its size on disk.
    last hardware sample / last proxied call
    How long ago the newest data arrived. No calls for a while is normal when nobody uses AI; no samples is not.

    Usage per model

    Source
    Where the model runs: a cloud provider, or local for a model on this machine.
    Calls, Input, Output
    Requests, and tokens sent to and generated by the model.
    Cache read, Cache write
    Tokens served from or saved to the provider's prompt cache. These are usually cheaper than normal input.
    Wh
    Energy used on this machine. For a cloud model this is near zero, because the work happens in the provider's data center.
    Cost
    Tokens times the model's price, plus its share of energy and fees.

    A - means the provider does not report that count, which is not the same as 0. A * after a name points to a note under Data issues.

    Data coverage

    For each day, how many hours the agent was actually measuring. A full bar is 24 hours (23 or 25 on daylight-saving days; today counts only the hours so far). Hours when the agent was not running are missing, not zero, so a short bar means the real energy and cost were higher than shown.

    Data issues

    A paid model has no price yet
    Its tokens count as $0 until an admin sets the price: aimeterix prices set MODEL --input 3 --output 15, or load the built-in list with aimeterix prices apply-reference.
    No cost profile
    Energy is measured but not priced. Set your electricity rate: aimeterix profile set --rate 0.30.
    Energy share is an estimate
    The chip reports total energy; the split between models and apps is estimated from how much each process used. Totals are measured, the split is an estimate.
    Batch tokens not metered yet
    Batch jobs are seen, but their tokens are not counted yet.
    Days with less than 90% measured
    See Data coverage.

    How cost is calculated

    Costs are never stored: they are computed from the measurements each time you look. For every hour:

    energy cost = kWh measured × PUE × rate per kWh
fee cost    = fixed fees per month ÷ hours in that month
token cost  = tokens ÷ 1,000,000 × price per 1M tokens (per token type)

    Energy and fees are then split between models, other apps and idle overhead by how much energy each used that hour. Each hour uses the price and profile in force at that time. aimeterix prices set corrects the current price everywhere it applies; add --from DAY to start a new price on that day and keep the old one before it. A new profile version applies from when it is saved.

    Prices, profile and settings

    Prices per 1M tokens
    What each model charges per million tokens, by token type, in USD. "not yet" means no price is set and its tokens show as $0.
    Cost profile
    Your electricity rate per kWh, the PUE (cooling and building overhead; 1.0 at home, 1.2 to 1.6 in a data center), and fixed running fees per month. Each change is saved as a new version.
    Live settings
    Settings the running services re-read about once a minute, without a restart:
    SettingWhat it does
    agent.interval_sSeconds between hardware samples (default 10).
    storage.raw_retention_daysDays to keep raw samples before only hourly totals remain (default 30).
    storage.rollup_retention_daysDays to keep hourly totals (default 365).
    proxy.default_upstreamWhere the proxy sends calls that match no named route, for example your local model server.
    proxy.upstreamsNamed routes, such as /openai/… to the OpenAI API.
    proxy.allowed_key_hashesIf set, only these API keys (stored as SHA-256 hashes, never the key itself) may use the proxy.

    Change them with aimeterix config set KEY VALUE; every change is logged with who and when (aimeterix config history KEY).

    Privacy and security

    • Only counts are stored: model names, token numbers, energy. Never prompts, answers or API keys.
    • The proxy, API and dashboard listen on this machine only (127.0.0.1) by default.
    • This page loads nothing from the internet: no fonts, scripts or trackers.
    • Passwords are stored as salted hashes. Sessions end on Log out.

    Troubleshooting

    The page does not open
    Run aimeterix health. If serve is stopped, run aimeterix start and check ~/.aimeterix/logs/serve.log.
    Calls or tokens stay at 0
    Your app is calling the model server directly. Point it at the proxy port, and check proxy.default_upstream points at the model server (aimeterix config).
    Energy stays at 0 or coverage is low
    The agent is not running or cannot read the sensors. Run aimeterix doctor to see what this machine can measure, then check ~/.aimeterix/logs/agent.log.
    Cost is $0
    Set a cost profile and model prices; see Data issues.
    "Port in use" at start
    Another program, or an old copy started by hand, already uses the port. Stop it, or run aimeterix stop first.

    Command reference

    Every command and option. Type aimeterix COMMAND --help for the same list in the terminal, and aimeterix --version for the version. With uv, put uv run in front of each command. Times are written 90s, 10m or 2h; days as YYYY-MM-DD.

    start, stop, health, agent, proxy, serve, doctor, usage, profile, prices, config, password

    Running: start, stop, health. Each service on its own: agent, proxy, serve. Checking: doctor, usage. Costs and settings: profile, prices, config, password.

    aimeterix start

    Starts the agent, proxy and API (serve) in the background, all three by default. They keep running after you close the terminal. Logs go to ~/.aimeterix/logs. If one is already running it is left alone.

    aimeterix start [agent] [proxy] [serve] [--config FILE]
    OptionWhat it does
    agent proxy serveStart only the ones you name. Default: all three.
    --config FILEUse this aimeterix.yaml instead of the default one.

    Examples

    aimeterix start   # everything
aimeterix start proxy   # only the proxy
aimeterix start agent serve   # measure and show, no proxy

    aimeterix stop

    Stops what start started. The agent and proxy write the data they hold in memory first. It then checks nothing is left running.

    aimeterix stop [agent] [proxy] [serve] [--keep-proxy] [--config FILE]
    OptionWhat it does
    agent proxy serveStop only the ones you name. Default: all three.
    --keep-proxyStop the others but leave the proxy running, so your apps keep working.
    --config FILEUse this aimeterix.yaml instead of the default one.

    Examples

    aimeterix stop   # everything
aimeterix stop --keep-proxy   # apps keep working
aimeterix stop serve   # only the API and dashboard

    aimeterix health

    Is everything running and measuring right now? Shows each service, the database, and the age of the newest sample and call. Exit code 0 when healthy, 1 when not, so scripts can use it.

    aimeterix health [--json] [--url URL] [--config FILE]
    OptionWhat it does
    --jsonPrint the report as JSON.
    --url URLUse this database instead of the one in the config, e.g. sqlite:///data/meter.db.
    --config FILEUse this aimeterix.yaml instead of the default one.

    Examples

    aimeterix health
aimeterix health --json   # for scripts and monitoring
aimeterix health || aimeterix start   # restart if something is down

    aimeterix agent

    Runs the measuring agent in this terminal (in the foreground) until you press Ctrl-C. start runs the same thing in the background.

    aimeterix agent [--interval SEC] [--burst TIME] [--for TIME] [--project NAME] [--mock] [--config FILE] [-v]
    OptionWhat it does
    --interval SECSeconds between samples, 1 to 300 (default from the live setting agent.interval_s, 10). Given here, it wins over the setting for this run.
    --burst TIMEFirst sample every second for this long, then fall back to the interval.
    --for TIMEStop by itself after this long: 90s, 10m, 2h. Handy for tests.
    --project NAMELabel this machine with a project name.
    --mockInvent readings instead of measuring, for a demo.
    --config FILEUse this aimeterix.yaml instead of the default one.
    -v, --verboseLog more detail.

    Examples

    aimeterix agent
aimeterix agent --interval 5 -v   # every 5 s, more logging
aimeterix agent --burst 2m --for 10m   # short detailed test

    aimeterix proxy

    Runs the proxy in this terminal until Ctrl-C. Your apps call it instead of the model server; it forwards each call unchanged and records the model and token counts.

    aimeterix proxy [--port PORT] [--upstream URL] [--route NAME=URL] [--for TIME] [--hash-key] [--config FILE] [-v]
    OptionWhat it does
    --port PORTPort on 127.0.0.1 to listen on (default 8787, or AIMETERIX_PROXY_PORT).
    --upstream URLWhere calls without a route name go, usually your local model server. Wins over the live setting proxy.default_upstream for this run.
    --route NAME=URLSend /NAME/... to URL. Repeat for more routes.
    --for TIMEStop by itself after this long: 90s, 10m, 2h. Handy for tests.
    --hash-keyRead an API key from the keyboard and print its hash, for proxy.allowed_key_hashes. The key itself is never stored.
    --config FILEUse this aimeterix.yaml instead of the default one.
    -v, --verboseLog the counts of every call.

    Examples

    aimeterix proxy --port 8080 --upstream http://127.0.0.1:8081   # llama.cpp on 8081
aimeterix proxy --route openai=https://api.openai.com   # apps call /openai/v1/...
aimeterix proxy --hash-key   # then paste the key

    aimeterix serve

    Runs the API and this dashboard in this terminal until Ctrl-C. First run creates the accounts user and admin.

    aimeterix serve [--host ADDR] [--port PORT] [--for TIME] [--url URL] [--config FILE] [-v]
    OptionWhat it does
    --host ADDRAddress to listen on (default 127.0.0.1, this machine only).
    --port PORTPort (default 8788).
    --for TIMEStop by itself after this long: 90s, 10m, 2h. Handy for tests.
    --url URLUse this database instead of the one in the config, e.g. sqlite:///data/meter.db.
    --config FILEUse this aimeterix.yaml instead of the default one.
    -v, --verboseLog every request.

    Examples

    aimeterix serve   # dashboard on 127.0.0.1:8788
aimeterix serve --port 9000

    aimeterix doctor

    Shows what this machine can measure: chip, sensors, power, GPU, and anything missing. Run it first on a new machine. It changes nothing.

    aimeterix doctor [--json] [--readings]
    OptionWhat it does
    --jsonPrint the report as JSON.
    --readingsWith --json, include the raw readings (no process names).

    Examples

    aimeterix doctor
aimeterix doctor --json --readings

    aimeterix usage

    Tokens, energy and cost per model and day, the same numbers as the dashboard.

    aimeterix usage [--from DAY] [--to DAY] [--last TIME] [--by day|model] [--csv FILE] [--url URL] [--config FILE]
    OptionWhat it does
    --from DAYFirst local day, YYYY-MM-DD (default today).
    --to DAYLast local day, included (default: the same day as --from, so one day).
    --last TIMEInstead of days: the last 24h, 90m, ...
    --by day|modelOne row per model and day (default), or one per model for the whole range.
    --csv FILEWrite CSV to FILE instead of a table. - prints it on screen.
    --url URLUse this database instead of the one in the config, e.g. sqlite:///data/meter.db.
    --config FILEUse this aimeterix.yaml instead of the default one.

    Examples

    aimeterix usage   # today
aimeterix usage --from 2026-10-01 --to 2026-10-31 --by model   # one month per model
aimeterix usage --last 24h
aimeterix usage --from 2026-10-01 --to 2026-10-31 --csv october.csv   # for a spreadsheet

    aimeterix profile

    Shows or sets this machine's cost profile: electricity rate, PUE and fixed fees. Each change is a new version that applies from when it is saved.

    aimeterix profile [show|set|history] [--rate N] [--pue N] [--fees N] [--spread calendar|uptime] [--name TEXT] [--region TEXT] [--host ID] [--url URL] [--config FILE]
    OptionWhat it does
    showShow the current profile (default).
    setSave a new version with the options given; the others stay as they were.
    historyList every version.
    --rate NElectricity price per kWh in USD, e.g. 0.30.
    --pue NCooling and building overhead: 1.0 at home, 1.2 to 1.6 in a data center.
    --fees NFixed running fees per month in USD (rent, internet, hardware lease), e.g. 60.
    --spread calendar|uptimeSpread fees over every hour of the month (calendar) or only the hours the machine ran (uptime).
    --name TEXTProfile name, e.g. home-office.
    --region TEXTA label only, e.g. CZ.
    --host IDWhich machine, when the database has more than one.
    --url URLUse this database instead of the one in the config, e.g. sqlite:///data/meter.db.
    --config FILEUse this aimeterix.yaml instead of the default one.

    Examples

    aimeterix profile
aimeterix profile set --rate 0.30 --pue 1.0 --fees 0   # home machine
aimeterix profile history

    aimeterix prices

    Shows or sets what each model costs per 1M tokens, in USD. Local models have no token price; their cost is their energy.

    aimeterix prices [list|set|history|reference|apply-reference] [MODEL] [--input N] [--output N] [--cache-read N] [--cache-write N] [--from DAY] [--local] [--dry-run] [--ignore-currency] [--url URL] [--config FILE]
    OptionWhat it does
    listShow the current price of every model seen (default).
    set MODELSet or correct a model's price. Without --from it corrects the current price everywhere it applies.
    history MODELEvery change to a model's price, with who and when.
    referenceShow the built-in list of public prices.
    apply-referenceCopy the built-in prices into your table. Models with no price get one; prices you set yourself start a new period today, so earlier days keep theirs.
    --input NPrice per 1M input tokens.
    --output NPrice per 1M output tokens.
    --cache-read NPrice per 1M tokens read from the prompt cache.
    --cache-write NPrice per 1M tokens written to the prompt cache.
    --from DAYStart the new price on this local day; earlier days keep the old price.
    --localThis model runs on this machine (no token price).
    --dry-runWith apply-reference: only show what would change.
    --ignore-currencyWith apply-reference: use the USD prices even if your profile uses another currency.
    --url URLUse this database instead of the one in the config, e.g. sqlite:///data/meter.db.
    --config FILEUse this aimeterix.yaml instead of the default one.

    Examples

    aimeterix prices
aimeterix prices set gpt-6-luna --input 0.10 --output 0.40
aimeterix prices set gpt-6-luna --output 0.50 --from 2026-11-01   # price rise from November
aimeterix prices set qwen3.5-35b-a3b --local
aimeterix prices apply-reference --dry-run   # preview first

    aimeterix config

    Shows or changes the live settings stored in the database. The running services pick up a change within about a minute; no restart needed. Every change is logged.

    aimeterix config [show|set|reset|history|export] [KEY|FILE] [VALUE] [--url URL] [--config FILE]

    The keys are listed under Prices, profile and settings.

    OptionWhat it does
    showEvery live setting and where its value comes from (default).
    set KEY VALUEChange one. VALUE is a number, text, null or JSON.
    reset KEYPut one back to its built-in default.
    history KEYEvery change, with who and when.
    export FILEWrite the whole configuration as YAML, without passwords. Never overwrites a file.
    --url URLUse this database instead of the one in the config, e.g. sqlite:///data/meter.db.
    --config FILEUse this aimeterix.yaml instead of the default one.

    Examples

    aimeterix config
aimeterix config set agent.interval_s 5
aimeterix config set proxy.default_upstream http://127.0.0.1:8081
aimeterix config set proxy.upstreams '{"openai": "https://api.openai.com"}'
aimeterix config reset agent.interval_s
aimeterix config export backup.yaml

    aimeterix password

    Sets the password of the user or admin account. Use it when a password is forgotten; it asks for the new one twice.

    aimeterix password user|admin [--url URL] [--config FILE]
    OptionWhat it does
    user | adminWhich account.
    --url URLUse this database instead of the one in the config, e.g. sqlite:///data/meter.db.
    --config FILEUse this aimeterix.yaml instead of the default one.

    Examples

    aimeterix password admin
